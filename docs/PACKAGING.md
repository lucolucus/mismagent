# Packaging and maintenance

How mismAgent is packaged as one plugin, how the same method is packaged for other agent
runtimes, and what keeps those packagings from drifting. For the method itself, see the
[README](../README.md).

## One plugin

- **`plugins/mismagent`** — explore, model, the worker-composer, and the worker's `realize-*`
  skills (one per block type). Sides are code/verification scopes inside the one repo; how a
  boundary crosses a network is a project choice, kept in its ADRs and gate.
- **`attic/`** — the superseded file-driven flow, kept out of the plugin registry on purpose.

## Supporting skills

Everything beyond the seven agents is a skill **invoked by the flow**; the internal ones carry
`user-invocable: false` (off the `/` menu, still loadable by the flow). `harvest-dev-architecture`
and `run-app-smoke` stay user entry points too:

| Skill | Movement | Role |
|---|---|---|
| `build-manifest` | model | Tactical model → building-block manifest (types pinned, `tests_nl`). |
| `readiness-gate` | model → build | Optional pre-flight survival test on the manifest. |
| `ux-designer` | model | Imagines the UI → views, when the feature has one. |
| `write-context-map`, `write-adr`, `write-code-rules`, `write-infra-notes`, `write-task` | explore/model | The writers — every cross-movement handoff is a file. |
| `realize-{aggregate, application-service, port, adapter, read-model, ui, scaffold}` | build | One skill per block type. `scaffold` is the greenfield wave-0 buildable skeleton. |
| `code-review` | build | Adversarial semantic review in fresh context. |
| `run-app-smoke` | build | The recorded render proof. |
| `harvest-dev-architecture` | build | Turns the first green slice's real conventions into the side's memory. |

## Other runtimes

The Claude Code plugin under `plugins/` is the **single source of truth**. `codex/` and `pi/` are
**generated views** — never edit them by hand; they ship no hooks
(the plugin's git guard is Claude-Code-only).

### Codex / OpenAI

`codex/` packages the method for **OpenAI Codex**: skills in `.agents/skills/` (`$mismagent-<name>`,
each with its `references/`), subagents as TOML in `.codex/agents/`, the methodology map as
`AGENTS.md`, `board.py` and `mismagent.py` inside the skills that call them. Regenerated by
`tools/generate-codex.py`.

```
codex/install.sh /path/to/your/project
```

### pi

`pi/` packages it for **[pi](https://pi.dev)**: skills in `.agents/skills/`
(`/skill:mismagent-<name>` — pi implements the same Agent Skills standard), the thin `[agent]`
commands as **prompt templates** in `.pi/prompts/` (`/mismagent-<name>`, with `$ARGUMENTS`
substituted natively), subagent definitions in `.pi/agents/` for pi's official `subagent` example
extension (called with `agentScope: "both"`; `mismagent-reviewer` is generated glue hosting
`code-review` in fresh context), and the methodology map as `AGENTS.md`. Regenerated by
`tools/generate-pi.py`.

```
pi/install.sh /path/to/your/project
```

Re-running an installer upgrades in place and removes the skills retired in v0.18.0; the old
`--with-cross-deploy` flag is refused.

`pi/` is also a pi package — `pi install <repo>/pi` covers skills and prompts globally, while agents
and `AGENTS.md` still come from `install.sh`.

## Keeping the derived views aligned

Both generators ship the methodology whole (only its title is replaced) and end with a
self-containment check: a Claude-only idiom, a relative link, a `.agents/skills/…` path or a
skill's `references/<file>` that does not resolve in the output fails the run with the list.

Two guards keep `codex/` and `pi/` in step with `plugins/`:

- **pre-commit hook**, versioned in `.githooks/`: a commit touching `plugins/` or either generator
  regenerates both trees and stages them in the same commit. Enable once per clone with
  `git config core.hooksPath .githooks`.
- **CI**, `.github/workflows/derived-views.yml`: pull requests to master fail if a derived tree is
  stale; a push to master **self-heals** — the workflow regenerates and commits the difference,
  which also reverts any hand edit to `codex/` or `pi/`.

## Prompt budgets

`plugins/mismagent/tools/budgets.json` caps the words of every operative prompt file (skills,
agents, commands, methodology, `PROFILE.md`), their total, the skills' `references/` (separately)
and every frontmatter description (250 characters). `prompt_budget.py` checks it inside the tool
tests; a new prompt file needs a budget, and a cap only goes down.
