# 0.7.28 plan — four defects a review of the harness reproduced

The human asked for a review of the harness as a black box (2026-11-10). Read against its own
claims — "`mm` owns the state, the git moves and every count", "hooks stop the agents from what is
not theirs" — four defects reproduced in a scratch repository:

1. **A builder could loosen its own gate.** The gate's settings live in the project's `CLAUDE.md`
   (`## mismagent`), a file the builder edits: `max_file_lines: 2000` and `suppressions: 50` in the
   slice's own commit, and `mm built` was green with nothing said.
2. **State was read from subjects typed by hand.** `next` knew a design pass had run from a commit
   whose subject starts `design pass`; `check --base` knew a change of the skill was the human's
   from a subject starting `conventions`. Both were typed by an agent following a prompt: `Design
   pass: …` with a capital asked for the pass again on every call, `Conventions: …` turned the gate
   red, and a builder's `specify: …` passed as the human's.
3. **The suppression sensor was blind outside Python, JavaScript, Go and Java**, and the size
   sensor exempted only `tests/` and the acceptance folders: on a Swift app `suppressions: 0`
   counted nothing and every XCTest file was held to `max_file_lines`.
4. **The git guard had gaps both ways**: `git pull`, `git commit -m x .` and `git add ./` passed;
   a commit message in a heredoc with a line starting `git push` was denied.

## Changes

- **Gate settings changed since Base** (`mm.py`, `run_check`): with `--base`, one warning per key
  of `## mismagent` that differs from `<base>:CLAUDE.md` (`GATE_KEYS`; not `shot`, the builder's to
  write). A warning, not an error: a migration slice changes `test:` by design. The reviewer's
  REWORK list names it: a setting loosened with no decision behind it.
- **A slice's `Base:` is mm's** (`base_moved`): everything the gate compares starts there, and the
  header sits in a file the builder edits. `check` fails when a doing slice's Base is no longer
  the one its file had in the last commit that moved it from todo/ to doing/ (`mm start`'s). The
  header is compared, not the history around it: a start commit cherry-picked or rebased keeps
  its Base; the file deleted and added again in doing/ is no new start.
- **`mm conventions "<note>" [--slice <s>] [files…]`** and **`mm designed "<note>" [files…]`**: mm
  writes the subjects it later reads. Both go through `commit_beside` (what `mm spec` was: the
  lock, HEAD read first, selected, checked, `publish`, again when HEAD moved). `designed` always
  commits — empty when the pass changed nothing — so `next` does not ask for the pass again. The
  conventions skill and the architect's design pass call them instead of committing by hand.
- **Named files in shared folders.** `conventions` takes the skill, the proposals and the design
  notes whole; `designed` the design notes and the proposals. Decisions, slices in todo, release
  files and the map are written by specify, a builder and the architect too, so there each commits
  only the files its caller names — that name exactly (a link stays the link, a deleted folder
  names none of its files), never a folder, never run debris — and lists what it left uncommitted.
  A slice among them naming an example with no row in a committed example file, or `After:` what
  is not exactly one slice among those committed and those of the same commit, is refused: the
  check reads the tree, the commit takes a part of it, and another session's draft — a row added
  or deleted, a slice written or removed — must change neither.
- **A backstop for subjects typed by hand**: `HUMAN_COMMIT` and `DESIGN_PASS` read `Specify …`,
  `Conventions: …`, `Design pass: …`, `design-pass …` in either case; a lookalike
  (`conventions-fix`, `Design passes`) stays nobody's.
- **`suppress:`** — the stack's own suppression markers, comma-separated plain text, counted on a
  line that contains one, beside the built-in ones (unchanged: no project turns red on an
  upgrade). One warning while the key is absent and a tracked source is in a language the
  built-ins miss. **`tests:`** — folders of tests outside `tests/`: no size limit there.
- **`guard-git.py`** reads the command as the shell does (`scan`): quotes, `$( )`, backticks and
  comments followed, so a `<<` inside a string opens nothing; a heredoc's body is text and is
  taken out only when what it feeds reads text (`cat`, `tee`, `git`), no shell is in the command
  and the shell would expand no substitution in it — else its lines are judged, as on 0.7.27,
  heredocs of their own included, in the directory they were fed in. The wrappers it knows are
  skipped with their options (`env -u X`, `timeout 30`, `nice -n 5`, `sudo -u bob`, `xargs`,
  `uv run`); a word that is only an argument (`printf '%s' git push`) runs nothing. It follows
  `cd`, `pushd`/`popd` and `git -C` to where git runs: a move inside a `( )` group ends with the
  group, one with an option leaves the directory unknown, never guessed. New denials: `pull`; an add or a commit of the
  whole tree however spelled (`./`, `src/..`, `..`, `**`, the root's absolute path, any pathspec
  magic but `:(literal)`); a commit whose subject as git keeps it (comment lines gone under a
  cleanup that strips them — asked for or configured — then the first paragraph, its lines joined)
  — typed, in a heredoc or a here-string, in a `-F` file, reused with `-C`, kept by `--amend` — starts
  with `specify`, `conventions`, `design pass` or a typed `Revert "specify…`; a commit whose
  message the hook cannot read (a file not there yet, a pipe, a directory it cannot follow: `-m`
  or `-F - <<'EOF'` says it); an `mm` subcommand of another role
  (`start`, `park`, `land`, `tag`, `conventions`: none of the three agents; `spec`, `designed`: the
  architect; `built`: the builder; `review`: the reviewer and the architect). A test ties the
  table to the agents' prompts.
- **`heal` by record, never by guess.** 0.7.27 took for its own leftover any path it publishes
  whose index entry differed from HEAD while the tree agreed with HEAD — which is also what a
  version someone staged and set aside looks like. Every `publish` now goes on record before the
  ref moves (`.git/mismagent.cut`: its commit, the shared index's entries under its paths, stage
  by stage) and off it once the index has followed — on the entries still as found, there too. Cut
  in between — a crash, an `index.lock` — the next move under the lock resets the entries still as
  that publish found them, and no other; one that cannot be reset yet, or whose commit git cannot
  place, stays on record. The record is replaced in one move, never rewritten in place; one mm
  cannot read or write refuses the move with nothing committed.

## Not done

A subject is a convention, not a signature: whoever can run `git commit-tree` can write
`specify …`. The hook denies the three agents the literal command and reads what the command
shows; a script, an alias or `sh -c` slips past it, as the hook's own text says. Accepting the
capitalised forms does not widen this: a route that passes the hook passes it in lower case too,
which 0.7.27 already read as the human's.

`base_moved` compares a header with the one committed at the start. A builder that rewrites its
own history below the start (a soft reset over `mm start`: git holds no trace of the first), or
replays a park and a start by hand (the file committed back in todo, then moved again: the first
start is still in history, but nothing tells mm's move from one made by hand), commits any Base
as the one the slice was started with. A soft reset is the builder's to rework its own commits.

The hook knows the wrappers in its table (`env`, `timeout`, `nice`, `sudo`, `xargs`, `uv run`,
…): git behind another one is not seen, as behind a script.

The shared index is not compared and reset in one step: `publish` and `heal` read the entries,
then reset those still as recorded. A version staged on one of mm's paths between the two —
milliseconds — is reset with them, as on 0.7.27 (whose reset compared nothing). Git gives no
compare-and-swap on the index short of holding `index.lock`, and an mm killed holding it would
stop every git command in the checkout.

`conventions --slice` commits the slice file whole, a builder's unfinished `## Progress` with the
answer: one file, two writers, as the conductor's own `## Answer` commit already is. `mm spec`
still takes the spec folders whole — the architect's stack review beside a live specify session
commits that session's files, as on 0.7.27.

A `conventions` or `design pass` commit is not read through by a review (`transparent`): one that
lands after a PASS and before `land` sends the slice back to `resume`. A catalog cannot be
committed topic by topic while a topic is incomplete: `conventions` refuses a skill with errors.

The review's other observations stay open: `marketplace.json` still describes the 0.26 flow; a
release review does not note HEAD first (known issue 4); `stuck` after `DIRECT` has no documented
exit in `build.md`; no test ties `build.md`'s action table to `decide()`; the gate runs three
times a round. And the larger one: from 0.5.0 to 0.7.28 the prompts doubled and `mm.py` tripled
while the hypotheses of `v0.5-hypotheses.md` and `bench/` stand as on 2026-10-01 — fifteen core
hypotheses, none confirmed or refuted, no long-horizon run recorded on 0.7.
