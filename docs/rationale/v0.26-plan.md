# v0.26 plan — existing code is an input of the whole flow

Revised after the user's review and a Codex review (11 findings, 7 HIGH): narrower contracts,
discovery advisory, the project's architecture authoritative, the folder/composer/proof model intact.

## Why
Run 6 (RegistratoreCassa6, R0+R1 released on v0.25.4) and a read of the core show that code already
written reaches no one who designs or plans:
- explore/model agents read only documents; the architect in `feature` mode never re-reads the
  modules or the composition root as built;
- the manifest has no way to say "this block changes that code": run 6 planned R1 work as notes on
  done R0 blocks (#33) and a composition block called a private method (#31);
- `MM pack` carries spec, boundaries and ADRs, but no path of the code the block changes or depends
  on; realize skills emit a `PUBLIC_API` line that nothing stores or packs.

## The rule (methodology, once; one line in each agent)
**Look at the relevant existing code before designing. Reuse it when its semantics and its
architectural placement fit; otherwise remodel it. A remodel or a duplicate is an explicit decision
(a decision note; an ADR when it changes the structure) with its reason, and its impact on the
existing code is planned as blocks — never silent. Existing code the work touches is rationalized
where it can be (duplicates merged, placement realigned to the current architecture), inside the
plan: blocks with `code_paths` whose tests prove the behavior preserved — only where it serves the
work at hand, never a detour.** The validation-mode exception stays: under
`greenfield_from_requirements`, prior implementations outside the project are not ground truth.

## What is "public" — the project's, never the core's
API semantics stay in the project's own dependency-lint configuration (`write-code-rules`), which
already enforces the published surface. The core only needs **discovery**, not authority: an
optional YAML section of `architecture.md` listing per module `{id, side, root, entry_files: […]}` —
*entry files* (where to start reading), explicitly not "the public API". No section → the codemap
groups by side and says modules are unknown.

## Changes (build order)
1. **#40** `release close|waive` refusals name the flags: `unexpected = given − allowed`,
   `missing = required − given`; exit codes unchanged.
2. **#39** release path: integrate the fix groups first, then ONE batch closure verification at the
   final tip; keep the cheap triage so already-fixed findings spawn no worker.
3. **#35–#37 handoff import, contextual and idempotent**: the worker writes its notes in a delimited
   section of the handoff; `MM why check H --into F/decisions.md --repo <worktree>` validates the
   projected append (links resolved as from decisions.md); the composer alone assigns final ids at
   append; import is idempotent (a retry adds nothing) and returns the id mapping. The template's id
   is a suggestion, never a reservation (parallel workers).
4. **#38** an un-parked worktree: the composer merges `B` into it (clean, idle) before the fresh
   pack; a conflict → the existing rework route; its HEAD is reviewed again. Not for checkpoint
   resumes (their proof binds the old HEAD).
5. **`MM codemap <output_dir> --ref <sha> [--side S] [--module M]`** — Markdown on stdout with its
   source sha: per side (profile `sides`), per module of the architecture section (else per
   directory), git-tracked files at that ref, entry files marked. Git inventory only — no
   provenance/last-touch attribution in this release. Brownfield works the same way.
6. **Side-scoped composition roots**: `composition_roots: {<side>: <path>}` in architecture.md,
   resolved by the block's side in render, lint and pack; the legacy scalar stays valid for a
   single-side project (fixes the first-token-wins ambiguity).
7. **Manifest `code_paths: [<repo-relative path>]`** (optional, new or deliberately revised rows
   only — never backfilled, so done blocks' spec_hash is untouched): the existing code a block
   changes; `after:` keeps scheduling. Works across features and for brownfield (no block ids
   needed). Lint: paths exist at the line's tip (or are marked new). Rule 19: later-release work that
   changes existing code is a block with `code_paths`; genuinely new work needs none.
8. **Wiring (prompts)**: `skills/explore` and `commands/model` pass a scoped codemap (module
   summary + the relevant entry paths; full inventory on demand) to analyst (context ↔ existing
   module mapping), challenger ("does existing code already do this, or nearly?"), researcher
   (project code first), tactical-modeler and ux-designer (reuse / remodel per the rule),
   architect (factual index vs architecture change: a drift is reported and amended through the
   existing checkpoint, never silently; declares the module section if absent), build-manifest
   (`code_paths`). The brief gets an "Exists / adds" section citing code, uncertainty stated.
   Harvest stays an optional route once enough verified code exists.
9. **Pack `## Existing code`**: the block's `code_paths` (modification targets) and the entry files
   of the modules it depends on (references, read-only); a composition block: its side's root and
   the entry files of its side's release blocks; release-group packs likewise. Worker/adapter
   wording: references are read, never written; the four `PUBLIC_API` return lines are dropped;
   manifest entry-point ACs (#31) and the dependency lint stay.

## Tests
Done-block hashes unchanged when an R1 block with `code_paths` is added; changing a block's
`code_paths` invalidates its own proof; two features; brownfield without architecture; two sides
with two composition roots; handoff import retries and parallel id collisions.

## Measure (structured scenario, phase E)
H8: the second feature has **no unjustified** duplicate of an existing aggregate, VO or screen, and
the existing behavior it touches is preserved (tactical model, manifest `code_paths`, code, the
acceptance scenarios of R0/R1 still passing).

## Budget
Prompt total stays ≤ 19 820 words (currently at the cap): every addition is funded by a deletion
(e.g. the four `PUBLIC_API` lines, duplicated reuse wording in worker/adapter); runtime pack size is
measured separately.

## Cut from this release
Authoritative `published_surface` globs; cross-feature `extends`; last-touch attribution; mandatory
harvest; full inventories in every prompt.
