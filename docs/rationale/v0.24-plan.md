# v0.24+ plan — the edges: releases, reuse, context cost, gate hygiene

*Rev. 3 — after three Codex passes (plan rev. 1 verification; reuse-strategy comparison; wave-planner
+ micro-steps verification) and the user's direction: reuse must be **logical** (seen in real code,
extracted the XP way), not predicted; token cost matters; a central coordinator may specialize work.*

## Evidence

A read-only design review of a real R0→R3 run (desktop app, 4 contexts, ~40k lines, ~200 blocks,
25 waves). The hexagonal core held; the debt is at the edges: releases survived as code layers,
cross-cutting mechanisms reinvented ~3× each, domain types leaking through public signatures, a
slow/fragile gate. ~2/3 of 191 deferred MED/LOW lines fall into ~10 patterns.

Cost (list-price estimate from the run's subagent transcripts): ~2 050 USD total. Worker dispatch
~8 USD avg; code-review ~1.5; verifier ~0.8; release re-verification ~6.5; release fixes so far
~265 with 191 lines still open. **Worker sessions:**

| quartile | median turns | final context | cost/call | cost/turn |
|---|---|---|---|---|
| shortest 25% | 21 | 73k | 0.66 | 0.031 |
| middle 50% | 63 | 195k | 3.79 | 0.058 |
| longest 25% | 135 | 391k | 21.63 | 0.110 |

The longest quarter is 73% of worker spend; cache reads are 83% of worker cost. Fresh sessions
cut the growing-history component; the achievable saving is **not** proven by these numbers
(Codex) — hence phase 1 measures before phases 3–4 build.

## Strategies considered for reuse (ranked with Codex)

S2 (workers report duplication, the composer extracts at a threshold) + advisory duplicate
detection > S2 alone > S1 (refactor agent every wave: pays when idle) > S5 (sequential, collective
ownership: ~4× build time on parallel waves) > S4 (predictive helpers: the "semantic" reuse the user
rejected) > S3 (workers extract themselves: contested ownership) > S0 (status quo).
A **wave planner** (central, just-in-time, on real code) is promising but only if it returns
evidence-backed pointers (`path#symbol`, signature, compatible behavior, legal import); "no search
hit" means "not found", not "missing". It is the last phase, gated on measured savings.

Constraint throughout: the prompt budget is full (19 809 / 19 820); every addition is paid by a cut;
bookkeeping goes into the tool, not into prose. Core text stays generic (no run specifics).

## Phase 1 — v0.24.0: structural fixes + fresh-context loop + measurement

### A — A release is a tag, not a layer in the code
- Manifest flag `composition: true`: at most **one block per (release, side)**; its `after:` lists
  every other block of that (release, side) — the single writer of the composition root, serialized
  by construction. The root is a **project location** named in `architecture.md`, not a block id.
- Lint: `composition.unique`, `composition.last`, `composition.root` (terminal lint too); legacy
  manifests without the flag: no new error.
- Worker golden rule (+1 clause): a `composition` block also writes in the composition location and
  **extends the existing composition in place, never wraps it**; other blocks expose their pieces
  from their own dirs. The block's `what` says so (the obligation reaches the worker via the spec).
- build-manifest rule 14 (+1 sentence) and rule 19 (+1 sentence): a release is a point on the line
  (its tag); no `tests_nl` asserts release history (a user-setting toggle stays testable).
- Risk to check: with a *manual* `ui_render_check`, the render proof of the release's `ui` blocks
  moves to its `composition` block (the first moment the app shows them).

### E — The published surface is checked on signatures, not only imports
- write-code-rules CA row: the rule checks the **declared published surface** (public signatures,
  nested types, re-exports) against its Published Language (pinned types, shared-kernel types,
  declared error shapes); the build graph does not re-export an inner module. Violating + conforming
  fixture.
- realize-scaffold: wire that check with the dependency lint.
- build-manifest: a limit/unit/identifier a consumer shows or validates is published by its owner
  through the boundary, never re-declared (how is the owner's design choice).

### F — Gate hygiene from the scaffold
- architect "Cheap, standard verification": build tool's standard parallel execution + cache on;
  `gate_verify` still forces execution.
- realize-scaffold: parallel + cache; **custom checks enumerate files git tracks or would track**
  (tracked + untracked-not-ignored), which excludes nested worktrees and build output; the
  compiler's own source discovery untouched.
- craft/tdd.md (within its 220 cap): time is an input — inject clock and scheduler; no real sleep to
  order events; wait with the stack's async assertion or the codebase's one helper.
- craft/clean-code.md: comments say what and why; review history lives in git and the feature folder.
- **Q1 (open, user):** default per-test timeout as a project test-runner convention (Codex: yes —
  deadlocks survive injected time; a hang that turns red is diagnosed). If yes, `LOOP.md` states how
  it differs from a harness watchdog.

### G — Fresh-context loop (the cost lever), no planner
- **Worker return `CHECKPOINT`** (new `RESULT` value): at a **green AC boundary**, once the session
  is long (soft target ~30–40 turns; never mid red/green), the worker commits and returns a compact
  checkpoint: done ACs, tests, next action, pending DECISIONS/DEVIATIONS. This is a context reset,
  not a watchdog: nothing is killed, the work continues in a fresh session.
- **Composer-owned re-dispatch:** on `CHECKPOINT` the composer records it and dispatches a fresh
  worker **in the same worktree** with a fresh `MM pack` + the checkpoint. One active session per
  block; parallelism across blocks unchanged; the full gate + verifier + review still once per
  block at `READY-FOR-REVIEW`.
- **Tool `MM progress record F <id> --head <sha> --spec-hash <h> --json <checkpoint>`** →
  `F/progress/<id>.json` (atomic; refuses a stale HEAD/spec hash). `MM status` exposes it in
  `resume`; a crash before recording = unverified work → inspect, never assume done (existing rule).
- **Pack diet:** a re-dispatch pack carries the checkpoint and only the advisory findings relevant
  to the block (not all open feature findings) — otherwise repeated packs erase the saving.
- Tests: record/refuse stale, status.resume shows it, re-entrance after a crash, no double dispatch.

### H — Measurement
- `bench/score.py` (or a small `bench/cost.py`): cost per **completed block** from transcripts —
  worker sessions (count, turns, cache reads), review, verifier, rework, checkpoints — and per wave.
  Compare runs with and without G on the same deliverable (Cassa).

## Phase 2 — v0.25: duplication evidence (cheap)
- Worker: before writing a general mechanism, a **bounded** search of the line; reuse when the
  evidence holds (`path#symbol`, compatible behavior, legal import). Otherwise write the minimum and
  return `DUPLICATES: [{mechanism, at, seen_at, differences}]` (no extra agent).
- Composer records candidates (single writer) in `F/duplicates.md` via a tool command; counts
  **distinct implementations**, not reports. Advisory clone detection over changed files (capped
  output) as extra evidence — never a gate (intended duplication exists: consumer-owned ports,
  per-consumer fixtures).

## Phase 3 — v0.26: evidence-triggered extraction (S2) + release grouping by cause
- Threshold: 3 uses, or 2 implementations confirmed behaviorally equal.
- **Durable barrier:** stop dispatching the affected blocks, drain the in-flight ones **through
  integration**, then extract from the line tip — else a sibling merges its copy back silently.
  Persisted across firings.
- The extraction is a **real manifest owner block** (build-manifest rule 8 incremental: added row,
  rendered, linted), with an explicit write scope (library destination + consumers' call sites),
  migrating all copies in the same task; both reviewers; pinned contracts unchanged. Next packs name
  its entry point. (Revises the earlier "no automatic extraction mid-build".)
- Release fallback: `release group --pattern --fix --owner` (cross-context, one side), fed by a
  release-mode review that clusters open lines by root cause; groups are the durable record.

## Phase 4 — trial: wave planner (only if phases 1–3 leave measurable duplication/cost)
- Read-only agent per explicit block batch (integration SHA + spec hashes), bounded search + bounded
  reading; returns **evidence-backed reuse pointers and shared-owner proposals**, steps may say
  "implement locally" or "investigate". The composer persists the advice (binding changes go to
  specs/ADRs); planner failure falls back to ordinary workers. Adopt only with measured net savings.
